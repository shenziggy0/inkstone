# 墨页与 Typora 全项目功能复测

2026-11-24，Apple Silicon Mac。对照对象为 Typora 官方签名的 1.14.15，与仓库冻结的版本一致。墨页使用本次工作树构建，并在编号列表修复预览包上另验点击与连续编辑。两端都打开同一份语料副本。测试范围包括仓库基准的七类 82 个条目，以及后来新增的导出、公式、表格、侧栏和列表专项。

**结论**　墨页自身的主回归通过。双端实测证明了一部分写作和渲染行为相同，也发现了能影响跨应用使用的差异。82 是核查范围，不能作为双端通过数。[冻结基准](../parity-baseline.md) · [双端导出原件与测试证据](2026-11-24-Typora双端复测证据.zip)

## 测试数据和范围说明

- `npm run build` 成功，`npm test` 共 256 项通过。主桌面脚本 `test/desktop.mjs` 完成 123 步。浏览器端标题和语法专项另有 90 个断言通过。
- 已运行工作台、编号列表、公式标签、图表、自定义主题、RFC 0001 桌面与渲染专项、导出、性能和截图脚本。桌面套件的部分用例预设文件选择结果或模拟输入法事件。另行验证的首次保存和 Pandoc 转换使用真实系统文件面板、实际文件与转换程序。
- 导出专项初跑缺少 `pdftotext`，指定本机已有的 Poppler 后通过。默认样例 PDF 为 4 页 A4，PNG 为 1912 × 6704。原交互式首次保存脚本因自动操作选错目标路径而超时，测试生成的文件已移回临时目录。重测指定临时目录作为真实面板的初始位置，核对了两个不同的图片引用和实际图片字节。
- 墨页在约 5千、3万、10万、22 万字符下保持排版，本机每键平均分别为 4.8、12.0、29.8、59.7 ms。22 万字符的 20 次输入记录到 20 个长任务。另测约 28 万字符进入源码回退。源码阈值为 260,000 个 UTF-16 码元；这组耗时只代表本机墨页。[性能用例](../../test/perf.mjs)
- Typora 基准来自官方签名的 macOS 1.14.15。Pandoc、参考应用和样例文档均放在临时测试位置。Typora 原生菜单还列有只读模式、图片上传、RTF、MediaWiki、Textile、OPML 等，本次墨页菜单或导出格式列表未发现对应入口。这些属于仓库原有 82 项之外也应跟踪的功能差距。[Typora 发布记录](https://typora.io/releases/stable) · [Typora 导出说明](https://support.typora.io/Export/)

## 对齐优先级

1. **跨应用链接能否打开。** 用两个和三个同名标题，以及本身带数字后缀的标题建立兼容用例。修改新锚点规则前验证旧墨页文档中已有链接的去向。
2. **用户输入同一段语法会看到什么。** 为高亮、上下标、行内公式、字数和无样式导出建立明确的 Typora 配置基线；将用户可选择的差异与实际行为缺失分别登记。
3. **操作手感和平台行为。** 用相同输入轨迹验证表格、嵌套列表、跨块选择、系统中文输入法和多窗口冲突。补齐 Windows/Linux 实机，以及 PDF、PNG、外部文档格式的输出对照后，再更新对应条目的对齐状态。
